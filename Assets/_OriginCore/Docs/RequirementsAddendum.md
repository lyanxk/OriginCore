# OriginCore 用户需求补充

更新时间：2026-07-31

本文件记录用户在分阶段验收中确认的需求变更。若这里的条目与
`DesignDocs/OriginCore_Codex_Implementation_Guide_Unity_2022.3.62f3.docx`
冲突，以本文件为准；后续实现、文档和按需验收都必须采用这里的规则。

## RQ-RTS-001：待确认指令与技能使用左键释放

- 点击 `Move`、`Attack`、定点/单位目标技能或 `Set Rally` 后进入待确认状态。
- 随后的世界空间目标在左键松开时确认；按住 Shift 时沿用追加队列规则。
- 进入待确认状态的那次 UI 左键点击不得立即确认目标。
- 待确认期间右键不得释放该指令或技能；使用明确的取消操作退出。
- 未处于待确认状态时，右键地面对移动单位保留默认 Move 语义；生产建筑采用 RQ-RTS-003 的直接集结语义。
- 本条覆盖指导文档 5.5、P08、P09 及后续阶段中“待释放使用右键”的旧定义。

## RQ-RTS-002：按命令类型显示虚线路线

- 被选中的可指挥移动单位若存在可显示路线的当前命令或等待命令，必须显示对应的世界空间虚线路线。
- `Move` 使用白色虚线；`Attack` 与 `AttackMove` 使用红色虚线；生产建筑的集结点路线继续使用白色虚线。
- 路线按可显示命令依次连接单位当前位置、当前命令目标与等待队列目标，顺序必须与实际执行顺序一致；每个命令段必须保留自己的颜色。
- 当前命令完成、替换、停止、队列推进或追加后，路线必须同步更新。
- 单位未选中、没有可显示目标、失效或死亡时隐藏路线。
- 表现参考旧项目的 `SelectionRoute`：世界空间 `LineRenderer`、重复虚线、清晰覆盖于测试场景表面；不得为每帧刷新产生托管内存分配。
- 技能按键及技能命令不生成命令路线；后续技能若复用命令队列，路线样式必须明确为 `None`，不得误用 Move/Attack 指示线。
- Move、Attack、AttackMove 与集结点继续使用统一路线源和复用渲染池，不得为每种命令另建互不兼容的绘制系统。

## RQ-RTS-003：生产建筑右键直接设置集结点

- 未处于任何待确认状态时，只要当前选择包含生产建筑，右键可达 NavMesh 地面就直接更新所有已选生产建筑的集结点。
- 该右键是生产建筑的默认语境指令，不进入待确认状态，也不使用 Shift 队列语义。
- 通过 `Set Rally` 按钮进入待确认状态时，仍必须按 RQ-RTS-001 使用后续左键释放确认；待确认期间右键不得确认集结点。
- 集结点更新后继续使用 RQ-RTS-002 的统一白色虚线路线显示。
- 集结点标记与路线必须使用不受地形深度遮挡的世界空间 Overlay 表现；即使目标位于坡面、凹地或被地形深度覆盖，玩家仍必须能看见指示。
- 生产生成器不得依赖 `Awake` 的脚本执行顺序绑定内容目录；从 Bootstrap、主菜单或直接进入 Gameplay Scene 时，正式 archetype 都必须在生成点按需解析并正常出兵。

## RQ-FPS-001：疾跑使用锁存输入

- FPS 中新的 `Sprint` 按下只负责进入疾跑加速阶段；再次按下不得作为关闭开关。
- 松开 `Sprint` 时，当前平面速度达到或超过独立配置 `sprintLatchMinSpeed` 才锁存疾跑；低于该速度则立即回到行走上限。
- 达标锁存后，松开或再次按下 `Sprint` 均不得降低目标速度；角色平面速度真正降至停止阈值后必须清除锁存，下一次移动从行走速度开始。
- 只有 `WasPressedThisFrame` 能发起疾跑；持续按住或从输入抑制帧延续的按住状态不得重新发起，也不得单独触发 Pending 手动接管。
- 下蹲或滑铲期间可保留尚未停止的疾跑状态，但移动上限按相应姿态处理；离开 FPS 时始终清除疾跑状态。
- 本条覆盖指导文档 P12 与输入矩阵中“按住 Sprint 使用疾跑上限”的旧定义。

## RQ-UI-001：Gameplay HUD 使用零边距贴边布局

- Gameplay HUD 的外层面板必须直接贴合其所属窗口边缘，不保留统一的 20px 浮动边距。
- RTS 小地图固定在左下角并保持 1:1 正方形；选择栏固定在底部中央；指令面板固定在右下角。
- RTS roster 贴左边缘，资源栏贴右上角；生产面板贴右边缘并位于指令面板上方，避免同时显示时互相遮挡。
- ACT HUD 固定在左上角；FPS HUD 固定在左下角。各模式根继续保持互斥显示。

## RQ-UI-002：取消模式/按键提示并图形化直控生命信息

- 不再显示 `MODE: RTS/ACT/FPS`、F1/F2/F3 模式提示或常驻鼠标/键盘操作提示。
- 指令和生产按钮只显示动作名称，不附带 `[LMB]`、`[A]`、`[S]` 等按键后缀。
- ACT 左上角改为 Health、Shield、Energy 图形条；FPS 使用同一实时数据源的图形条，不再显示数值文本。
- 直控图形条必须绑定当前 `PossessionService.CurrentPawn` 的 `VitalsComponent`，并随 Pawn 切换和 Vitals 事件刷新。

## RQ-UI-003：RTS 资源与世界生命条实时呈现

- RTS 右上角 Commander、Crystal、Influence 必须在一行内显示，并继续由 `ResourceService` 事件驱动刷新。
- 所有可受伤单位/建筑的世界空间 Health/Shield 条必须与 `VitalsComponent` 实际值同步；受伤后即使画布此前因满血而关闭，也必须立即显示正确比例。
- 世界生命条保留事件刷新，并增加轻量的数值变化兜底检查，避免启用顺序、对象重启或遗漏事件导致显示停留在旧值。

## RQ-UI-004：RTS 指令面板使用 4×4 正方形槽位布局

- 右下角指令面板保持零边距贴边，并固定为 360×360 的 1:1 正方形。
- 面板必须完整划分为 4×4、共 16 个等尺寸正方形指令槽，不再在面板下方显示 `COMMANDS/WAITING`、目标提示、队列摘要或反馈文本。
- 可移动单位选中时，Move、Attack、Stop、Cancel 占据第一行四个槽位，不再横向铺满窗口底边。仅选中建筑或矿物资源点时不得显示 Move；Move 槽保持为空，其他基础指令及动态指令维持固定槽位，不得向前补位或改变玩家已建立的位置记忆。
- 其余十二个槽位是通用动态指令槽，可用于技能、建设、生产、研究、晋升、部署或武器交易；无有效 descriptor 时不得拦截指针输入或伪装成已实现内容。
- 生产面板继续贴右边缘，并随正方形面板高度上移到其正上方，不得发生重叠。

## RQ-UI-005：资源栏右贴边、指令槽完整边框与旧资源迁移

- RTS 资源栏根与文字都必须右对齐到窗口最右边；文字不得继续从一个右上角宽容器的左侧开始显示，也不保留额外右侧内边距。
- 4×4 指令面板的十六个槽位必须使用一致且完整的四边框。任意相邻列之间都必须同时看见第一列右边框与第二列左边框，不得因实际按钮缺少边框组件而断线。
- 面板使用统一暗色半透明底板、外框和阴影；基础指令与动态指令使用可辨识的分类强调色、顶部高光和一致的悬停/按下/禁用状态。空槽保持低对比度，不能与可执行指令争夺视觉注意力。
- 旧项目中可复用的 UI 资源必须复制到 `_OriginCore` 自有目录并获得独立 GUID，不能让新场景继续引用 `Assets/Resources` 旧路径，也不能移动原文件破坏旧系统。
- 第一批迁移包含三个指令图标和四个 RTS 能力图标。Move、Attack、Stop 接入已有功能按钮；尚未迁移 Runtime 行为的能力图标只保存为资产，不显示为可用按钮。

## RQ-MAINT-001：需求直接落地，不再维护阶段工具

- 新增或调整需求必须直接落实到 Runtime、场景、Prefab、配置或其他实际资产，并同步更新本文件及相关架构/状态文档；只写文档不视为完成。
- `Tools/OriginCore` 下的 P01～P16 Apply、Validate 和 Build 自动化已经退役，后续改动不得重新依赖或要求运行这些菜单。
- 后续改动不再回写旧阶段生成器或 Validator；默认只做程序集编译与 Unity Console Error/Warning 清洁检查。Test Runner、Play Mode、Profiler 和 Player 构建仅在用户明确要求时执行。

## RQ-VIS-001：战争迷雾使用世界坐标黑色遮罩

- `VisibilityGrid` 的 Hidden、Explored、Visible 三态及其 Alpha 遮罩继续作为唯一权威数据，不改变敌人显隐、建筑记忆、小地图过滤或存档语义。
- Main Camera 使用 Camera Depth 重建当前可见表面的世界坐标，并以世界 XZ 精确采样同一张可见性纹理；不得再沿视线做体积积分、噪声漂移或高度密度变化。
- 当前不可见的 Hidden 与 Explored 区域均显示纯黑，Visible 区域透明；遮罩只覆盖 `MapDefinition.WorldBounds`，天空和地图边界外不绘制战争迷雾。
- 小地图直接把同一张三态 fog texture 作为 UI 遮罩叠加，不创建 `FogOverlayPlane`、专用小地图 Camera 或 RenderTexture；三个 URP 质量档必须装配同一个黑色战争迷雾 Renderer Feature。
- 表现层不得依赖每帧 CPU 纹理生成或托管分配；CPU 继续只做低频三态遮罩更新，GPU 每像素只做一次深度重建和一次遮罩采样。
- `MapDefinition.WorldBounds` 是对局内 Visibility、世界遮罩和场景边界的共同权威。每张 Gameplay 场景必须在该范围四周生成四面无 Renderer、非 Trigger 的空气墙，阻止地面单位、直控角色和飞行单位离开场景；直接运行没有 MatchConfiguration 的系统测试场景时回退到 `VisibilityBounds`。
- 可见区过渡不得泄露隐藏敌人或改变可选取、锁定与存档语义。本条覆盖并废止此前采用动态平面雾及体积雾的表现方案。

## RQ-MAP-001：小地图由地图数据独立绘制

- 每张地图必须提供自己的 `MinimapMapDefinition` 或手绘底图；底图只在地图定义变化时重建，不得从任何 Unity Camera、Camera CullingMask、视口位置或 RenderTexture 采集。
- 单位、英雄和建筑标记必须由 `EntityRegistry`、Faction、Role、世界坐标和 Visibility 状态映射为 UI 标记；移动单位只更新对应标记，不重新拍摄或重绘底图。
- Hidden/Explored/Visible 遮罩直接叠加在 UI；隐藏敌人不得显示，已探索建筑记忆使用最后已知坐标，不读取不可见实体的实时位置。
- RTS 相机移动、缩放和模式切换不得改变小地图底图、迷雾或实体标记。小地图点击可以把归一化坐标转换为世界坐标并控制 RTS Camera Rig，但相机只作为操作结果，不是地图画面的输入。
- 新地图必须让 `MinimapMapDefinition`、`MinimapBounds` 和 `VisibilityBounds` 使用同一 XZ 范围；未配置独立地图定义时视为场景配置不完整。

## RQ-RTS-004：RTS 相机只做直接平移与即时定位

- 地图首次进入 RTS 玩法时，Camera Rig 必须立即以当前友方主基地为中心；优先选择具备生产/出生与资源回收能力的可工作建筑。没有显式初始目标时才使用这一确定性查找规则。
- 初始输入快照中的默认指针坐标不得触发边缘移动；收到一次真实指针位置变化后才启用边缘移动，避免镜头在玩家尚未操作时从基地漂向地图边界。
- RTS 边缘移动只平移 Camera Rig，不允许环绕、摇头或因追随/构图阻尼产生临时旋转。
- 点击小地图后直接定位到目标世界坐标，不播放平滑追踪或转向动画。
- 滚轮只改变相机高度和与目标的距离，俯角固定为 60°，缩放过程中不得改变朝向。
- RTS Cinemachine Transposer 与 Composer 的位置、Lookahead 和构图阻尼必须为 0；边界约束、UI/失焦门控和非 RTS 拒绝小地图点击的规则保持不变。

## RQ-RTS-005：建筑、矿物与炮台能力边界

- `ResourceNode` 在实体角色上同时标记为 `Building`，但保持 Neutral、不可选择、无 `UnitCommandQueue`、无 `NavMeshAgent` 与无移动驱动；它是静态采集建筑，不能显示或接收 Move。
- 任何没有完整移动命令管线的建筑都不得因为隐藏 Move 而重排其余指令槽。
- 建筑不显示 Move、Attack 或 Stop；这些手动指令只属于拥有对应 `UnitCommandQueue` 的单位。炮台使用自动索敌攻击链，不显示无法执行的手动 Attack/Stop；隐藏后其余 4×4 指令仍保持原槽位，不向前补位。
- 炮台完成建造并进入 Operational 后，以低频、无分配扫描自动选择可见敌对目标，通过既有 `AttackCapability`、Faction 与 `DamageReceiver` 管线攻击，不建立第二套伤害执行器。
- 在正式平衡值输入前，炮台使用可配置实现基线：Range 10、Damage 10、Cooldown 0.5 秒；这些值属于占位平衡数据，可只改 `SO_Unit_Z_turret` 替换。

## RQ-PRES-001：灰盒角色统一球体与移动浮动

- 所有 Hero、Worker、普通单位、Z 单位与敌方单位的角色本体统一使用一个球体 `VisualRoot`；选择圈、世界血条、相机 Target、碰撞体和功能性武器/能力表现不计入角色本体，不得被合并进球体。
- 替换只发生在表现层。Prefab 根的 `EntityIdentity`、Collider/CharacterController、NavMeshAgent、移动驱动、命令队列、伤害与存档组件必须保持原有语义。
- 角色移动时只让 `VisualRoot` 沿本地 Y 轴周期上下浮动；不得移动 Prefab 根、碰撞体、选择圈、血条或权威世界坐标。
- 浮动必须同时覆盖 RTS NavMesh 移动和 ACT/FPS 直接控制移动，并可通过根位移识别战斗位移；停止后平滑回到基准高度，暂停时冻结，Disable 时恢复基准位置。
- 当前不引入 Animator、AnimationClip 或伪造的正式待机/攻击动画；正式动作动画不是当前交付前置条件。
- 所有球体角色必须挂载 `AttackEffectPresentation`。普通攻击、通用枪械和 WeaponAction 通过既有攻击事件触发短暂光束与命中脉冲，以程序化攻击特效代替攻击动作；友方使用青色、敌方使用红色、中立使用黄色。
- 攻击特效只允许消费既有攻击/命中事件，不得发起伤害、改变命中范围、冷却、资源消耗、位移或命令状态；特效节点只在运行时创建、不得带有效碰撞体，暂停时不推进。
- 受击闪白、弹体、战斗位移与 Final Wing 等已有程序化效果继续独立运行，并可与通用攻击特效叠加。

## RQ-PRES-002：Y 武器技能程序化特效

- 时隙之钥、时序之键与终焉之翼的全部 39 个 WeaponAction 必须拥有与设计描述对应的程序化特效；只实现特效，不创建 Animator、AnimationClip、骨骼动作或模型动作。
- 时隙之钥使用青蓝色剑痕体系，区分斜斩/反斩、穿行残影、重斩、旋转斩、冲刺轨迹、45° 剑气、裂隙、瞬移斩、挑空和下砸冲击。
- 时序之键使用紫色镰刀体系，区分正反镰斩、水平/纵向旋转、五把幻影镰刀、投出与回收路径、冻结锚点的持续旋转镰刀、三周纵斩、勾取、强力斩和砸地冲击。
- 终焉之翼使用金白色羽翼体系：普通攻击显示六条分方向穿越/返回轨迹，持续技循环发射六翼，背向爆发、下方挑起分别采用对应方向；两个终结技必须分别显示六边形对角斩与“镰刀顺转、羽翼反转”的双向轨道。
- 专属特效必须优先于 `AttackEffectPresentation` 的通用 WeaponAction 光束，命中仍显示短暂脉冲。特效只消费 ActionStarted、ActionEnded 与 HitApplied，不得参与伤害、命中、控制、位移、冷却、资源或目标选择。
- 特效节点仅运行时创建，无 Collider，使用缩放时间，动作结束、取消、切换形态、死亡或 Disable 时必须淡出或清理；不得序列化到 Prefab/Scene。

## RQ-DIRECT-001：直控目标锁定与武器轮盘

- ACT 按住 Shift 锁定当前可见、存活、敌对且在配置距离内的最近目标；锁定后保持该目标，直到松开、目标失效/死亡/越界或离开 ACT，不因出现更近目标自动切换。
- 锁定只控制 ACT Camera 朝向，不直接移动 Pawn 或目标，也不得读取 VisibilityGrid 判定为隐藏的敌人。
- ACT 的 Q/E 循环已有武器；ACT 与 FPS 的 Tab 都打开中央武器轮盘，松开后确认选择。
- 直控 Cursor 锁定时，轮盘必须使用鼠标 Look 位移累积选择，不依赖冻结的绝对鼠标坐标；轮盘打开期间相机不得同时转动。
- FPS 轮盘对未装备候选复用武器购买/替换/返还事务，并显示购买成本和返还值；失败不得留下半装备或丢失资源。

## RQ-FPS-002：Hero 专属投掷物接口

- FPS 短按 4 装备或循环当前 Hero 可用投掷物；按住 4 达到阈值后打开投掷物轮盘，松开确认。
- 投掷物装备后左键只执行一次投掷，不得同时开火；按 1/2/3、离开 FPS 或输入被抑制时解除投掷物装备。
- 每次投掷先原子扣除定义化 ResourceCost；生成或初始化失败必须退款。范围伤害统一经过 FactionRelations 与 DamageReceiver。
- 投掷物名称、Crystal 成本、伤害、范围、模型和 Hero 列表在原设计中为空。Runtime 与 UI 接口必须存在，但在正式内容输入前保持定义数组为空，不虚构可用内容。
